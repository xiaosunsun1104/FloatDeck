# 登录状态跨启动保存（版本保持 1.0）

用户已实际登录成功，但次日启动丢失登录。此前仅使用 `persist:duoview-video` 分区，没有恢复会话 Cookie，也没有在退出时等待 Cookie 写入。持久分区不等于保留所有类型的 Cookie，不能把“用了 persist”作为登录必然保留的证据。

新增 `session-state.cjs`：用系统提供的异步加密保存会话 Cookie，启动时在网页加载前恢复，Cookie 变化后更新，正常退出时等待最后一次写入并刷新浏览器存储。文件在用户数据目录，不在源码或发布包中。不收集密码、不输出 Cookie 值、不向外发送凭据。原有网站数据和持久 Cookie 保留，恢复不覆盖已有同名/域/路径 Cookie，不更改过期时间。网站注销导致 Cookie 删除时更新保存文件，避免下次启动错误恢复。加密或写入失败会在主界面提示。

验证命令：`node scripts/test-session-restart.cjs`。使用独立测试目录和虚构 Cookie，跨三个真实 Electron 进程验证保存、恢复、HttpOnly/Secure/SameSite/域与路径属性、已有持久 Cookie、加密文件无明文值，以及注销后的再次启动不恢复。配置测试和桌面冒烟测试通过。未登录真实账号，未向抖音连续发送测试请求。

限制：已经被旧版丢失且磁盘上不存在的登录凭据无法凭空恢复；网站服务器仍可以撤销登录或要求重新验证。此次修复不能证明用户昨天丢失状态必然只由会话 Cookie 导致，但补齐了应用侧明确的保存缺口。

## 后续真实问题与完整备份

用户更新后再次反馈登录丢失。最初读取旧 Cookie 库与版本 1 备份未见常见登录标记，但这次检查不完整，不能据此断言凭据已丢失。随后通过实际浏览器 Session 生成的完整备份确认两站登录标记均存在；新启动后各打开一次首页，B站显示账号头像，抖音放大后显示账号头像及消息提醒，检查过程中没有重新登录。至少本次启动实际保留了两站登录，不能将此前的反馈统一归因于网站过期。小窗裁切账号区域会影响用户判断，历史掉登录的确切原因仍未确定。

现将加密备份升级为版本 2，同时覆盖会话与未过期的长期 Cookie，恢复时保留原到期时间，不覆盖现有 Cookie、不恢复已过期 Cookie。保留对版本 1 的读取。增加仅包含保存时间、数量和启动恢复数量的状态摘要，方便后续比较，不包含 Cookie 名称、值或账号信息。

新增真实多进程用例：在隔离测试目录中移开浏览器 Cookie 数据库，再由加密备份恢复两类 Cookie；验证主动注销后不恢复；验证旧版版本 1 文件升级后两类 Cookie 保留。这些用例均已通过，仍不能等同于真实账号升级前后验证。本次更新前另存本地加密记录、Cookie 数据库和 Local State，备份位于用户数据目录，不进入源码或发布包。

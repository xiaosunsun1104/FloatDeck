# 登录保存与发布兼容检查（2026-10-31，版本仍为 1.0）

用户再次反馈启动后需要登录，并要求兼容发布到 GitHub 后其他人的本机使用。本次没有复现真实账号失效：检查更新前的抖音网页时显示原账号头像和消息；关闭旧桌面版、替换软件文件并从原快捷方式启动后，B站与抖音均显示原账号头像，期间没有扫码、验证码或重新登录操作。这说明本次更新与重开保留了当前账号，不能据此承诺网站永远不让登录过期，也不能断言历史掉登录的唯一原因。

检查确认原有 userData、sessionData 与实际 Session.storagePath 都指向同一份 AppData 数据，未发现目录分叉。之前保存时间停留在昨天只是一条线索：无 Cookie 变化时不会定期重写备份，不能据此判定启动失败。新增启动摘要用于直接区分启动、恢复与保存时间。

## 本次改动

- 在 ready 前明确将 userData 与 sessionData 固定到当前用户的 AppData/duoview，沿用现有资料，不迁移或清空。安装目录、桌面快捷方式、版本号不参与路径计算。
- 未取得单实例锁时立即结束模块执行，第二次启动不会继续初始化网页分区或保存同一份资料。
- 单条 Cookie 恢复失败不再中断整个保存器；失败记录仍留在加密备份中，后续网站修改或删除优先于旧记录。
- 无法读取的加密备份先另存原文件，当前原生网页数据和后续登录仍可保存；系统加密暂不可用时保留原备份，并继续刷新原生网页存储。
- 保存原生网页数据先于加密备份；连续 Cookie 更新时最长两秒触发一次备份，避免防抖一直延迟。退出等待网页关闭后再做最终保存，涵盖 pagehide 的最后写入。
- 登录保存警告独立常驻，其他操作反馈不会盖掉。诊断只含目录、时间、数量、变化原因汇总，不含 Cookie 名称、值或账号信息。
- “网页登录”改为“放大网页”，并解释此按钮不代表已退出账号；只调整查看大小，沿用原会话。
- GitHub 检查工作流加入登录生命周期测试，没有上传真实用户资料，也没有执行发布。

`npm run test:session`：旧备份升级、原生 Cookie 库缺失后的恢复、HttpOnly/Secure/SameSite 属性、注销不复活、坏记录不阻断后续保存、损坏备份原件保留、加密不可用时原件不被覆盖、连续变化时保存均通过。

打包生命周期测试使用实际 Electron 桌面运行方式、生产 main/preload/IPC/窗口创建逻辑及独立的模拟资料目录：首次保存 → 开发运行 → 移动后的桌面版 → 注销 → 原安装目录再次启动。验证 Cookie 真正发送到本地 HTTP 服务，localStorage、IndexedDB 与页面关闭时写入都保留。另一个模拟用户目录没有继承账号。重复启动只唤起原实例。全部通过。测试仅使用本地虚构账号，没有代替用户操作网站登录。

真实账号检查：本机桌面版更新与重开后，两站原账号仍显示，无需重新登录。没有进行跨 Windows 账号、跨物理设备或隔天的真实账号测试。

一般界面冒烟测试：当前环境连独立最简 Electron 窗口的 isAlwaysOnTop() 都返回 false；未修改产品置顶行为。默认冒烟测试会报告此失败。明确设置 FLOATDECK_ALLOW_NO_TOPMOST_TEST=1 后，其余十窗口、视频控制、界面与快捷键检查通过；报告明确记录置顶检查被跳过，不将其计入已通过项目。

## 发布行为

每个使用者在自己的 Windows 账号下首次登录，资料留在各自本机。开发者资料不进入源码或发布压缩包；不导入 Edge 凭据。移动解压目录与更新软件不改变资料目录。网站撤销会话、到期、安全验证、清理 AppData 或更换 Windows 账号仍可能需要重新登录；其他网站和其他硬件的真实兼容性不由本机测试替代。

## 运行中保存与中断恢复补强

进一步检查确认，Windows 关机/重启不一定触发 Electron 的 will-quit。已添加主窗口 query-session-end 的尽力保存，并继续以运行中的变化保存为主，不把正常退出当作唯一保障。

新增 session-files.cjs：加密临时文件写完后调用文件同步，再提交只包含 SHA-256 的检查点，随后替换主文件并同步当前恢复副本。读取时只接受当前检查点匹配的主文件、已提交临时文件或恢复副本。这样中断重命名后可恢复已提交的新记录；损坏主文件可从同一代副本恢复；已退出账号时，早一代仍可解密的登录副本也不能自动恢复。原来的单文件版本仍可原地升级，不清空账号。

保存失败会自动退避重试，不要求用户为了临时写入错误重启或重登。合并重复保存请求，频繁 Cookie 变化时限制普通保存频率；显式删除和过期删除优先保存，正常退出等待最终保存。没有持续空转轮询全部用户资料。

增加文件恢复测试、临时加密写入失败后自动恢复测试和真实加密旧副本不能撤销注销的测试。打包流程新增：模拟 Windows 关机通知 → 等待后台检查点 → app.exit(73) 跳过正常退出保存 → 损坏测试主文件并移开测试原生 Cookie 数据库 → 在开发版中恢复并向本地服务发送会话 Cookie。继续验证换目录、用户隔离及注销，全部通过。未重启用户电脑，未模拟真实突然断电；测试不会读取真实账号。断电发生在最新变化提交之前、磁盘不可写或网站撤销凭证时，仍不能承诺永不重登。
